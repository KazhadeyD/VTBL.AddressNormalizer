## 1. Глоссарий

Общие элементы .NET `System.Text.RegularExpressions`, которые встречаются почти в каждом indoor-паттерне.

| Конструкция | Значение |
|-------------|----------|
| `^` | Начало строки (якорь). |
| `$` | Конец строки (якорь). |
| `.` | Любой символ (кроме `\n` при обычных опциях). В литерале пишется как `\.`. |
| `\.` | Литеральная точка. |
| `\?` | Литеральный знак `?` (редко). Не путать с квантификатором `?`. |
| `?` (после атома) | Квантификатор «0 или 1» (опционально). |
| `*` | Квантификатор «0 или более». |
| `+` | Квантификатор «1 или более». |
| `{n}` | Ровно `n` повторений. |
| `{n,}` | Не меньше `n` повторений. |
| `{n,m}` | От `n` до `m` повторений. |
| `\|` | Альтернатива («или») внутри группы или на верхнем уровне. |
| `(…)` | Захватывающая группа (номерная). |
| `(?:…)` | Незахватывающая группа (только группировка/альтернативы). |
| `(?<name>…)` | Именованная захватывающая группа (`v`, `headers`, `start`, …). |
| `(?<!…)` | Negative lookbehind: слева **не** должно быть `…`. |
| `(?!…)` | Negative lookahead: справа **не** должно быть `…`. |
| `(?<=…)` | Positive lookbehind: слева должно быть `…`. |
| `(?=…)` | Positive lookahead: справа должно быть `…`. |
| `\p{L}` | Unicode-категория «буква» (любой алфавит). В C# verbatim/`$@` часто экранируется как `\p{{L}}`. |
| `(?<!\p{L})` | Слева нет буквы → левая «граница слова» для кириллицы/латиницы. |
| `(?!\p{L})` | Справа нет буквы → правая граница. |
| `\d` | Цифра (`0`–`9`). |
| `\w` | «Слово»: буква, цифра или `_` (зависит от культуры; с `CultureInvariant` — стабильнее). |
| `\s` | Пробельный символ (пробел, таб, перевод строки и т.п.). |
| `\b` | Граница слова (между `\w` и не-`\w`). Для кириллицы в .NET обычно работает, но indoor чаще использует `\p{L}`-lookaround. |
| `[…]` | Класс символов: любой из перечисленных. |
| `[^…]` | Инвертированный класс: любой **кроме** перечисленных. |
| `[\d\w\-]` | Цифра **или** `\w` **или** дефис. Дефис в конце/`\-`, чтобы не задать диапазон. |
| `\s*` / `\s+` | Ноль или более / один или более пробельных. |
| `RegexOptions.IgnoreCase` | Без учёта регистра. |
| `RegexOptions.CultureInvariant` | Сравнения без культурных сюрпризов. |
| `RegexOptions.Compiled` | Компиляция в IL при старте (быстрее на горячем пути). |

**Типичный каркас indoor-маркера:**

```text
(?<!\p{L})(?:ЛЕКСЕМА)(?!\p{L})
```

- слева не буква → не матчить середину слова («ПОДЪЕЗД» внутри «…ПОДЪЕЗДА…» с буквой справа отсекается правым lookaround);
- `(?:ЛЕКСЕМА)` — альтернативы маркера без лишнего захвата;
- справа не буква → не откусывать префикс от более длинного слова.

**Группа значения** почти везде: `(?<v>…)`.

## 2. Лексемы `IndoorMarkerLexemes`

Файл: `Infrastructure/Shared/IndoorMarkerLexemes.cs`  
Это **не** самостоятельные `Regex`, а тела альтернатив `(?:…)` для фабрики и парсера.

### 2.1. `Apartment` = `КВАРТИРА|КВ`

| Фрагмент | Смысл |
|----------|--------|
| `КВАРТИРА` | Полная форма. |
| `\|` | Или. |
| `КВ` | Сокращение (точку добавляет фабрика через `\.?`). |

### 2.2. `Cabinet` = `КАБИНЕТ|КАБ`

Аналогично: полное / краткое.

### 2.3. `Office` = `ОФИС|ОФ`

Аналогично.

### 2.4. `Entrance` = `ПОДЪЕЗД`

Одна форма без альтернатив.

### 2.5. `Passage` = `ПРОЕЗД|ПР-Д`

| Фрагмент | Смысл |
|----------|--------|
| `ПРОЕЗД` | Полная форма. |
| `ПР-Д` | Сокращение с литеральным дефисом. |

### 2.6. `Holding` = `ВЛАДЕНИЕ|ВЛАД(?!\p{L})|ВЛ`

| Фрагмент | Смысл |
|----------|--------|
| `ВЛАДЕНИЕ` | Полная форма. |
| `ВЛАД(?!\p{L})` | «ВЛАД», справа не буква — чтобы не съесть начало «ВЛАДЕНИЕ» как `ВЛАД` + хвост (порядок альтернатив: длинная раньше). |
| `ВЛ` | Кратчайшее; точку снаружи даёт фабрика. |

### 2.7. `Storage` = `СКЛАД|СКЛ`

Полное / краткое; `\.?` снаружи у Holding/Storage в `IndoorMarkerPatterns`.

### 2.8. `Block` = `БЛОК`

### 2.9. `Section` = `СЕКЦ`

Префикс без полной формы (для `MarkerPrefix` / сокращений).

### 2.10. `SectionFull` = `СЕКЦИЯ`

Полное слово для парсера (`SectionRegex`, `BlockSectionRegex`).

### 2.11. `Mailbox` = `А/Я`

Литералы `А`, `/`, `Я`.

### 2.12. `Litera` = `ЛИТЕ?РА?`

| Фрагмент | Смысл |
|----------|--------|
| `ЛИТ` | База. |
| `Е?` | Опциональная «Е» → `ЛИТ` / `ЛИТЕ`. |
| `РА?` | «Р» + опциональная «А» → `ЛИТР`/`ЛИТЕРА` и укорочения вроде `ЛИТ`. |

Фактически покрывает семейство «литера / лит / …».

### 2.13. `Floor` = `ЭТАЖ|ЭТ(?!\p{L})|Э(?!\p{L})|ПОДВАЛЬНЫЙ|ПОДВАЛ|ЦОКОЛЬНЫЙ|ЦОКОЛ`

| Фрагмент | Смысл |
|----------|--------|
| `ЭТАЖ` | Полное. |
| `ЭТ(?!\p{L})` | «ЭТ», не начало более длинного слова на букву. |
| `Э(?!\p{L})` | Одиночная «Э» как маркер этажа. |
| `ПОДВАЛЬНЫЙ` / `ПОДВАЛ` | Подземный уровень. |
| `ЦОКОЛЬНЫЙ` / `ЦОКОЛ` | Цоколь. |

### 2.14. `FloorMarker` = `ЭТАЖ|ЭТ(?!\p{L})|Э(?!\p{L})`

Только «этаж» без подвал/цоколь — для typed-regex парсера.

### 2.15. `Premise` = `НЕЖ\.?\s*ПОМ|ПОМЕЩЕНИЯ|ПОМЕЩЕНИЕ|ПОМЕЩ|ПОМ`

| Фрагмент | Смысл |
|----------|--------|
| `НЕЖ\.?\s*ПОМ` | «НЕЖ. ПОМ» / «НЕЖ ПОМ»: `НЕЖ`, опциональная точка, пробелы, `ПОМ`. |
| `ПОМЕЩЕНИЯ` … `ПОМ` | От полной формы к краткой (длинные раньше). |

### 2.16. `Room` = `КОМНАТА|КОМН|КОМ|КО`

Длинные формы раньше коротких.

### 2.17. `ShortRoom` = `К\.`

Буква `К` + обязательная точка (в extract; в парсере short-room ослаблен до `К\.?`).

### 2.18. `Workplace` = `РАБ\.?\s*М(?:ЕСТО|ЕСТ|ЕС)?\.?|Р\.?\s*М\.?`

| Фрагмент | Смысл |
|----------|--------|
| `РАБ\.?` | «РАБ» / «РАБ.». |
| `\s*` | Пробелы между «РАБ» и «М…». |
| `М(?:ЕСТО|ЕСТ|ЕС)?` | `М`, опционально хвост МЕСТО / МЕСТ / МЕС. |
| `\.?` | Опциональная точка после. |
| `\|` | Или краткая ветка. |
| `Р\.?\s*М\.?` | «РМ», «Р.М.», «Р М» и т.п. |

### 2.19. `Part` = `Ч\.?\s*П`

«Ч.П», «Ч П», «ЧП»: `Ч`, опциональная точка, пробелы, `П`.

## 3. Фабрика `IndoorMarkerRegexFactory`

Файл: `Infrastructure/Shared/IndoorMarkerRegexFactory.cs`  
Общие опции: `IgnoreCase | CultureInvariant | Compiled` (`MarkerOptions`).

### 3.1. `MarkerOnly(lexeme)`

**Шаблон:** `(?<!\p{L})(?:{lexeme})(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| `(?<!\p{L})` | Левая граница (см. глоссарий). |
| `(?:{lexeme})` | Подстановка лексемы. |
| `(?!\p{L})` | Правая граница. |

**Назначение:** только детект маркера (extract), без значения.

### 3.2. `MarkerPrefix(lexeme)`

**Шаблон:** `(?<!\p{L})(?:{lexeme})`

Как `MarkerOnly`, но **без** правого `(?!\p{L})` — для префиксов (`СЕКЦ…`, `РАБ.М…`), где справа могут идти буквы/точки маркера.

### 3.3. `MarkerThenDigitValue(lexeme, optionalTrailingDot=true)`

**Шаблон:** `(?<!\p{L})(?:{lexeme})\.?\s*(?<v>\d[\d\w\-/]*)`  
(если `optionalTrailingDot=false`, фрагмент `\.?` отсутствует)

| Фрагмент | Смысл |
|---------|--------|
| `\.?` | Опциональная точка после маркера («КВ.»). |
| `\s*` | Пробелы до значения. |
| `(?<v>…)` | Именованный захват значения. |
| `\d` | Значение **обязано** начинаться с цифры. |
| `[\d\w\-/]*` | Дальше: цифры, `\w`, `-`, `/`. |

**Пример:** `ВЛАДЕНИЕ 1`, `СКЛ. 12А`.

### 3.4. `MarkerThenDigitValueList(lexeme, …)`

**Шаблон:**  
`(?<!\p{L})(?:{lexeme})\.?\s*(?<v>\d[\d\w\-/]*(?:\s*[,;]\s*\d[\d\w\-/]*)*)`

| Фрагмент | Смысл |
|---------|--------|
| Первое `\d[\d\w\-/]*` | Первое значение с цифры. |
| `(?: … )*` | Ноль или более хвостов списка. |
| `\s*[,;]\s*` | Разделитель `,` или `;` с пробелами. |
| `\d[\d\w\-/]*` | Следующее значение снова с цифры. |

**Пример:** `КВАРТИРА 13К1, 3, 6`.

### 3.5. `MarkerThenOptionalToken(lexeme, valuePattern=[\d\w\-]+)`

**Шаблон:** `(?<!\p{L})(?:{lexeme})\s*(?<v>{valuePattern})?`

| Фрагмент | Смысл |
|---------|--------|
| `\s*` | Пробелы. |
| `(?<v>…)?` | Значение **опционально**. |
| `[\d\w\-]+` (по умолчанию) | Один или более: цифра/`\w`/дефис. |

**Пример:** `БЛОК`, `БЛОК Е`, `А/Я 165`.

### 3.6. `MarkerThenRequiredToken(lexeme, valuePattern=[\d\w\-]+)`

**Шаблон:** `(?<!\p{L})(?:{lexeme})\s*(?<v>{valuePattern})`

Как предыдущий, но значение **обязательно**.

**Пример:** `ЛИТЕРА А`.

## 4. Маркеры extract `IndoorMarkerPatterns`

Файл: `Infrastructure/Shared/IndoorMarkerPatterns.cs`  
Используются в outdoor/indoor split (`BuildingLocationExtractor` / registry).

Ниже — **итоговый** смысл; границы и опции — из фабрики, если не указано иное.

### 4.1. `Floor` → `MarkerOnly(Floor)`

Детект этажа/подвала/цоколя по лексеме `Floor`.

### 4.2. `Premise` → `MarkerOnly(Premise)`

Детект помещения / «неж. пом».

### 4.3. `Room` (кастомный)

**Паттерн:**  
`(?<!\p{L})(?:КОМНАТА|КОМН|КОМ|КО)(?!\p{L})|(?<!\p{L})К\.(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| Первая ветка | Полные/краткие «комната» с обеими границами. |
| `\|` | Или. |
| `(?<!\p{L})К\.(?!\p{L})` | Отдельно «К.» (`ShortRoom`) с границами. |

### 4.4. `Office` / `Apartment` / `Cabinet` / `Entrance` / `Block` / `Mailbox`

`MarkerOnly` соответствующих лексем.

### 4.5. `Workplace` / `Part` / `Section`

`MarkerPrefix` — без жёсткой правой границы буквы.

### 4.6. `Passage` (кастомный)

**Паттерн:**  
`(?<!\p{L})(?:\d+\s*-\s*[ЙЯ]\s+)?(?:ПРОЕЗД|ПР-Д)(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| `(?:\d+\s*-\s*[ЙЯ]\s+)?` | Опциональный порядковый префикс «1-й », «2-я ». |
| `\d+` | Число. |
| `\s*-\s*` | Дефис с пробелами. |
| `[ЙЯ]` | Буква окончания порядкового. |
| `\s+` | Пробел(ы) перед словом «проезд». |
| `(?:ПРОЕЗД|ПР-Д)` | Лексема проезда. |
| `(?!\p{L})` | Правая граница. |

### 4.7. `Holding` → `MarkerOnly(Holding + \.?)`

Лексема владения + опциональная точка в теле маркера.

### 4.8. `Storage` → `MarkerOnly(Storage + \.?)`

Аналогично для склада.

## 5. Парсер `BuildingUnitParser.Patterns`

Файл: `Infrastructure/BuildingUnit/BuildingUnitParser.Patterns.cs`  
Класс: `BuildingUnitParser` (partial).

Если не указано иное: `IgnoreCase | CultureInvariant | Compiled` (или `MarkerOptions`).

### 5.1. `WhitespaceCollapseRegex` = `\s+`

| Фрагмент | Смысл |
|---------|--------|
| `\s+` | Один или более пробельных → замена на один пробел / trim. |

**Где:** `Preprocess`, после extract, `NormalizeValue`.

### 5.2. `ApartmentRegex` / `CabinetRegex`

`MarkerThenDigitValueList(Apartment|Cabinet)` — см. §3.4.

### 5.3. `EntranceRegex`

**Паттерн:**  
`(?<!\p{L})ПОДЪЕЗД(?:/ЭТАЖ|/ЭТ)?\s*(?<v>[\d\w\-/]+)?`

| Фрагмент | Смысл |
|---------|--------|
| `ПОДЪЕЗД` | Маркер. |
| `(?:/ЭТАЖ|/ЭТ)?` | Опциональный хвост «/ЭТАЖ» или «/ЭТ» (подъезд/этаж в одной записи). |
| `\s*` | Пробелы. |
| `(?<v>[\d\w\-/]+)?` | Опциональное значение: цифры/`\w`/`-`/`/`. |

**Примеры:** `ПОДЪЕЗД 5`, `ПОДЪЕЗД/ЭТ 2`.

### 5.4. `PassageRegex`

**Паттерн:**  
`(?<!\p{L})(?:(?:ПРОЕЗД|ПР-Д)\.?\s*(?<v>\d[\d\w\-/]*)|(?<v>\d+)\s*-\s*[ЙЯ]\s+(?:ПРОЕЗД|ПР-Д))`

| Фрагмент | Смысл |
|---------|--------|
| Ветка 1 | Маркер (с опц. точкой) + значение с цифры. |
| Ветка 2 | «N-й/-я ПРОЕЗД» без отдельного номера после слова: число берётся из порядкового `(?<v>\d+)`. |

### 5.5. `HoldingRegex` / `StorageRegex`

`MarkerThenDigitValue` — см. §3.3.

### 5.6. `BlockSectionRegex`

**Паттерн:**  
`(?<!\p{L})БЛОК-СЕКЦИЯ\s*(?<v>[\d\w\-]+)?`

| Фрагмент | Смысл |
|---------|--------|
| `БЛОК-СЕКЦИЯ` | Составной маркер (литеральный дефис). |
| `\s*` | Пробелы. |
| `(?<v>[\d\w\-]+)?` | Опциональный номер. |

Обрабатывается **до** обычного `BlockRegex`.

### 5.7. `BlockRegex`

`MarkerThenOptionalToken(Block)` — см. §3.5.

### 5.8. `SlashChainHeaderTokenPattern` (константа)

```text
ЭТАЖ|ЭТ\.?|Э\.?|ПОМЕЩЕНИЯ|ПОМЕЩЕНИЕ|ПОМЕЩ\.?|ПОМ\.?|КОМНАТА|КОМН\.?|КОМ\.?|КО\.?|ОФИС|ОФ\.?|КАБИНЕТ|КАБ\.?|РАБ\.?\s*М(?:ЕСТО|ЕСТ|ЕС)?\.?|Р\.?\s*М\.?
```

Токен **типа** в slash-цепочке: этаж/помещение/комната/офис/кабинет/раб.место с опциональными точками.  
`ЭТ\.?` / `Э\.?` — «ЭТ», «ЭТ.», «Э», «Э.»; аналогично сокращениям пом/ком/оф/каб.  
Хвост про workplace — как в лексеме `Workplace`.

### 5.9. `SlashChainHeaderChainRegex`

**Паттерн:**  
`(?<headers>(?:{Token})(?:[/.-](?:{Token}))+)`

| Фрагмент | Смысл |
|---------|--------|
| `(?<headers>…)` | Вся цепочка заголовков. |
| `(?:{Token})` | Первый тип. |
| `(?:[/.-](?:{Token}))+` | Один или более разделителей `/` `.` `-` и следующий тип. |

**Пример:** `ЭТАЖ/ПОМЕЩ.`, `КОМ./ОФИС`.

### 5.10. `NextSlashHeaderClusterBoundaryRegex`

**Паттерн:**  
`\s+(?:,\s*)?\s*(?:{Token})[./]`

| Фрагмент | Смысл |
|---------|--------|
| `\s+` | Обязательный пробельный разрыв перед новым кластером. |
| `(?:,\s*)?` | Опциональная запятая с пробелами. |
| `\s*` | Ещё пробелы. |
| `(?:{Token})` | Начало следующего заголовка. |
| `[./]` | Сразу точка или слэш после токена (признак header-chain, не «КОМ 5»). |

Останавливает захват значений перед следующим «КОМ./ОФИС …».

### 5.11. `PremiseRoomCompoundRegex`

**Паттерн:** `^(?<premise>[\d\w]+)-(?<room>\d+[\w]*)$`

| Фрагмент | Смысл |
|---------|--------|
| `^`…`$` | Весь токен. |
| `(?<premise>[\d\w]+)` | Левая часть (римские/буквы/цифры). |
| `-` | Дефис. |
| `(?<room>\d+[\w]*)` | Комната: начинается с цифры, далее опционально `\w`. |

**Пример:** `XII-8` → premise=`XII`, room=`8`.

### 5.12. `SlashChainHeaderTokenRegex`

Паттерн = сам `SlashChainHeaderTokenPattern` — поочерёдный разбор токенов внутри `headers`.

### 5.13. `InterleavedTypedSlashChainRegex`

**Паттерн:**  
`(?<!\p{L})(?:{Token})\s*[\d\w\-]+(?:\s*/\s*(?:{Token})\s*[\d\w\-]+)+`

| Фрагмент | Смысл |
|---------|--------|
| Маркер + значение | Первый сегмент. |
| `(?:\s*/\s*маркер\s*значение)+` | Минимум ещё один сегмент через `/`. |

**Отличие от header-chain:** маркер стоит **перед каждым** значением (`помещ 3/ком 4/оф 23`), а не списком типов сразу.

### 5.14. `InterleavedTypedSlashSegmentRegex`

**Паттерн:** `^(?<h>{Token})\s*(?<v>[\d\w\-]+)$`

Разбор одного сегмента после разрезания цепочки: группа `h` — тип, `v` — значение.

### 5.15. `SectionRegex`

**Паттерн:**  
`(?<!\p{L})СЕКЦИЯ\s*(?:НОМЕР\s*)?(?<v>[\d\w\-]+)?`

| Фрагмент | Смысл |
|---------|--------|
| `СЕКЦИЯ` | Полный маркер. |
| `(?:НОМЕР\s*)?` | Опциональное слово «НОМЕР». |
| `(?<v>…)?` | Опциональный номер. |

**Примеры:** `СЕКЦИЯ 1`, `СЕКЦИЯ НОМЕР 2`.

### 5.16. `MailboxRegex` / `LiteraRegex`

`MarkerThenOptionalToken(Mailbox)` / `MarkerThenRequiredToken(Litera)`.

### 5.17. `BusinessCenterNoteRegex`

**Паттерн:**  
`(?:\(\s*(?<v>БЦ[^)]*)\s*\))|(?<v>БЦ\s*[^\d,;()]+(?:\s+[^\d,;()]+)*)`

| Фрагмент | Смысл |
|---------|--------|
| Ветка 1 `\(` … `\)` | Текст в скобках. |
| `\s*` | Пробелы у скобок. |
| `(?<v>БЦ[^)]*)` | «БЦ» и всё до закрывающей `)`. |
| Ветка 2 | «БЦ …» без скобок. |
| `БЦ\s*` | Префикс БЦ и пробелы. |
| `[^\d,;()]+` | Кусок текста **без** цифр и `,;()`. |
| `(?:\s+[^\d,;()]+)*` | Дополнительные слова через пробел, пока не встретится цифра/разделитель. |

**Примеры:** `(БЦ Речной Вокзал)`, `БЦ Альфа`.

### 5.18. `RangeRegex`

**Паттерн:** `^(?<v>\d+[А-ЯA-Z]?\s*-\s*\d+[А-ЯA-Z]?)$`

| Фрагмент | Смысл |
|---------|--------|
| `\d+` | Число слева/справа. |
| `[А-ЯA-Z]?` | Опциональная одна буква (кириллица заглавная / латиница). |
| `\s*-\s*` | Дефис диапазона. |
| `^…$` | Весь raw-code токен. |

Попадает в `диап:`. **Пример:** `74-82`, `1А-8Б`.

### 5.19. `DashGapRegex`

**Паттерн:** `(?<=[\d\p{L}])\s*-\s*(?=[\d\p{L}])`

| Фрагмент | Смысл |
|---------|--------|
| `(?<=[\d\p{L}])` | Слева цифра или буква. |
| `\s*-\s*` | Дефис с пробелами (заменяется на `-`). |
| `(?=[\d\p{L}])` | Справа цифра или буква. |

**Пример:** `74 - 82` → `74-82`. Не ломает логику «1-Й» на этапе strip отдельно.

### 5.20. `SlashTypeHeaderRegex`

**Паттерн:** `(?:ЭТ|ПОМЕЩ|КОМ)\.\/?\s*|(?:ОФИС)(?:\./|\.\s+|\s+)`

| Фрагмент | Смысл |
|---------|--------|
| `(?:ЭТ|ПОМЕЩ|КОМ)` | Сокращения типов. |
| `\.` | Обязательная точка. |
| `\/?` | Опциональный `/` после точки. |
| `\s*` | Пробелы. |
| Ветка `ОФИС` | Без обязательной точки: `\./` **или** `.\s+` **или** `\s+`. |

Не матчит голый `ЭТ 3` без точки/слэша в этой нотации.

### 5.21. `SlashTypeTokenRegex` = `ЭТ|ПОМЕЩ|КОМ|ОФИС`

Извлечение имени типа из совпадения заголовка.

### 5.22. `FloorTypedRegex`

**Паттерн:**  
`(?<!\p{L})(?:ЭТАЖ|ЭТ(?!\p{L})|Э(?!\p{L}))\.?\s*(?<v>[\d\w\-]+(?:/[\d\w\-]+)*)(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| `FloorMarker` | Этаж без подвал/цоколь. |
| `\.?` | Опциональная точка. |
| `(?<v>[\d\w\-]+(?:/[\d\w\-]+)*)` | Значение и опциональные хвосты через `/`. |
| `(?!\p{L})` | Правая граница значения. |

### 5.23. `PremiseTypedRegex`

**Паттерн:**  
`(?<!\p{L})(?:ПОМЕЩЕНИЯ|ПОМЕЩЕНИЕ|ПОМЕЩ|ПОМ)(?!\p{L})\.?\s*(?<v>[^,\s;]+(?:\s*,\s*(?=\d)[^,\s;]+)*)`

| Фрагмент | Смысл |
|---------|--------|
| Маркеры помещения | Без «НЕЖ.ПОМ» в этой typed-ветке (явный список). |
| `(?!\p{L})` | Правая граница маркера. |
| `(?<v>[^,\s;]+` | Значение: всё, кроме `,`, пробела, `;`. |
| `(?:\s*,\s*(?=\d)[^,\s;]+)*` | Список через запятую, **только если** следующий кусок начинается с цифры (`(?=\d)`). |

### 5.24. `RoomTypedRegex`

**Паттерн:**  
`(?<!\p{L})(?:КОМНАТА|КОМН|КОМ|КО)(?!\./)(?!\p{L})\.?\s*(?<v>[\d\w\.\-/;]+)(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| `(?!\./)` | Не заголовок slash-нотации «КОМ./». |
| `(?<v>[\d\w\.\-/;]+)` | Номера с `.` `-` `/` `;`. |

### 5.25. `ShortRoomTypedRegex`

**Паттерн:** `(?<!\p{L})К\.?\s*(?<v>\d[\d\w\-]*(?:/[\d\w\-]+)*)(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| `К\.?` | «К» или «К.». |
| `(?<v>\d…)` | Значение **только с цифры** — защита от «Курьяновски», «КВАРТИРНЫЙ». |

### 5.26. `OfficeTypedRegex`

**Паттерн:**  
`(?<!\p{L})(?:ОФИС|ОФ)\.?\s*(?<v>[\d\w\-]+(?:/[\d\w\-]+)*)(?!\p{L})`

Стандартный typed-маркер офиса.

### 5.27. `WorkplaceTypedRegex`

**Паттерн:**  
`(?<!\p{L})(?:{Workplace})\s*(?<v>[\d\w\-]+)(?!\p{L})`

Лексема рабочего места + обязательное значение без `/`-цепочки в группе `v` (одна «порция» `[\d\w\-]+`).

### 5.28. `PartTypedRegex`

**Паттерн:**  
`(?<!\p{L})Ч\.?\s*П\.?\s*(?<v>[\d\w\-]+)(?!\p{L})`  
(фактически: лексема `Part` = `Ч\.?\s*П`, затем ещё `\.?\s*` в шаблоне парсера)

| Фрагмент | Смысл |
|---------|--------|
| `Ч\.?\s*П` | «ч.п» / «ч п». |
| `\.?` | Ещё одна опциональная точка после `П`. |
| `(?<v>[\d\w\-]+)` | Номер части. |

### 5.29. `NoteRegex`

**Паттерн:**  
`(?<!\p{L})(?:ВХОД\s+С\s+ТОРЦА|ВХОД\s+С\s+ФАСАДА)(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| `ВХОД\s+С\s+ТОРЦА` | Фиксированная фраза с пробелами. |
| `\|` | Или «ВХОД С ФАСАДА». |

Уходит в `note:`, не в типы номеров.

### 5.30. `OrdinalSuffixStripRegex`

**Паттерн:** `(\d+)\s*-\s*([ЙЯ])\b`

| Фрагмент | Смысл |
|---------|--------|
| `(\d+)` | Число → `$1` при replace. |
| `\s*-\s*` | Дефис порядкового. |
| `([ЙЯ])` | Только «Й» или «Я». |
| `\b` | Граница слова — не трогает `5-20`, `27-Н`. |

**Пример:** `1-Й` → `1`.

### 5.31. `BareFloorWordRegex`

**Паттерн:** `\bЭТАЖ\b(?!\s+[\d\w])`

| Фрагмент | Смысл |
|---------|--------|
| `\bЭТАЖ\b` | Целое слово «ЭТАЖ». |
| `(?!\s+[\d\w])` | После него нет пробела + цифробуквенного значения. |

Удаляет голое «ЭТАЖ» (например перед «ЦОКОЛЬНЫЙ»), не трогает `ЭТАЖ 4`.

### 5.32. `RawCodeTokenRegex`

**Паттерн:** `^[\d\w\-./]+$`

Весь токен — «кодоподобный»: цифры, `\w`, `-`, `.`, `/`. → `code:`.

### 5.33. `LetterWordTokenRegex`

**Паттерн:** `^\p{L}{2,}$`

| Фрагмент | Смысл |
|---------|--------|
| `\p{L}{2,}` | Только буквы, длина ≥ 2. |

Голое слово → `note:` (не римское — римские отсекаются отдельно нормализатором).

Схлопывание пробелов во входной адресной строке.

### 7.2. `LeadingPostalIndexLabelRegex`

**Паттерн:** `^(?:индекс|index)\s*:?\s*\d{6}\s*,\s*`

|---------|--------|

Тот же индекс без слова «индекс».

### 7.4. `BuildingLocationExtractor.HouseNumberMarkerRegex`

| Фрагмент | Смысл |
|---------|--------|
| `(?:ДОМ|Д)` | Маркер дома. |
| `(?!\p{L})` | Правая граница маркера. |
| `\.?` | Опциональная точка. |

### 7.5. `AbbreviationPunctuationStep.TrailingDotAfterType`

## 8. Синонимы геотипов

### 8.1. Шаблон `RegexSynonymNormalizer`

Файл: `Infrastructure/Shared/RegexSynonymNormalizer.cs`  
Для каждого `SynonymRule.Pattern`:

**Шаблон:** `(?<!\p{L})(?:{rule.Pattern})\.?(?!\p{L})`

| Фрагмент | Смысл |
|---------|--------|
| Границы буквы | Целый токен. |
| `(?:{Pattern})` | Альтернативы из правила (`город|гор|г`). |
| `\.?` | Опциональная точка у сокращения. |
| Replace | На `rule.Replacement`. |

Опции: `IgnoreCase | CultureInvariant | Compiled`.

### 8.2. Правила `GeographicTypeSynonymRules`

Файл: `Infrastructure/BuildingAddress/GeographicTypeSynonymRules.cs`  
В regex попадает поле `Pattern` (левая колонка):

| Pattern (альтернативы) | Replacement |
|------------------------|-------------|
| `город|гор|г` | `г` |
| `улица|ул` | `ул` |
| `дом|д` | `д` |
| `корпус|корп` | `корп` |
| `строение|стр` | `стр` |
| `литера|лит` | `лит` |
| `проспект|просп|пр-кт|пр` | `пр-кт` |
| `переулок|пер` | `пер` |
| `бульвар|бул|б-р` | `б-р` |
| `шоссе|ш` | `ш` |
| `область|обл` | `обл` |
| `район|р-н` | `р-н` |
| `посёлок|поселок|пос|п` | `п` |
| `село|с` | `с` |

Длинные формы в списке раньше коротких — порядок правил важен.

Каждая альтернатива в `Pattern` — литеральный текст (дефис в `пр-кт`, `р-н`, `б-р` — обычный символ `-` внутри `(?:…)`).
